## explain-changes — 바뀐 코드, 쉬운 말로 설명받기

Claude Code에서 코드를 수정한 뒤 "무엇이 왜 바뀌었는지"를 쉬운 말로 정리해 주는 스킬입니다.

### 왜 만들었나

**불편했던 점**

Next.js + Supabase로 Todo 앱을 만들면서, AI가 코드를 고쳐 줄 때마다 무엇이 바뀌었는지 잘 이해가 되지 않았습니다.
그래서 매번 "방금 바꾼 거 쉽게 설명해 줘", "어려운 용어 빼고 다시 설명해 줘"를 반복해서 입력해야 했습니다.
설명을 받아도 이론이 길거나 용어가 많아서, 정작 화면에서 뭐가 달라졌는지는 알기 어려웠습니다.

**스킬로 해결한 점**

- 변경 직후 한마디만 하면 `git diff` 기준으로 실제 바뀐 부분만 설명합니다.
- 항상 같은 순서(한 줄 요약 → 화면 변화 → 바뀐 파일 → 용어 풀이 → 확인 방법)로 나와서 읽기 편합니다.
- 처음 보는 Next.js·React 용어는 비유와 함께 한 줄로 풀어 줍니다.
- Supabase 테이블·권한(RLS)·환경 변수를 건드린 변경은 따로 알려 줍니다.
- 매번 "쉽게, 짧게, 용어 풀어서"를 다시 설명할 필요가 없어졌습니다.

### 설치 위치

이 저장소의 `.claude/skills/explain-changes` 폴더를 적용할 프로젝트 루트에 복사합니다.

```
<적용할 프로젝트>/.claude/skills/explain-changes/SKILL.md
```

스킬 폴더를 처음 넣었다면 Claude Code를 한 번 재시작해야 인식됩니다.

### 호출 문장

프로젝트를 Claude Code로 연 상태에서 새 대화를 시작하고, 코드를 수정한 뒤 이렇게 말합니다.

```
방금 바꾼 거 쉽게 설명해 줘
```

"뭐 바뀌었어?", "변경사항 정리해 줘"처럼 말해도 발동됩니다.

### 실제 확인한 결과

- 적용 프로젝트: [gsahn26/todo-app](https://github.com/gsahn26/todo-app) (Next.js + React + Supabase + Tailwind)
- 설치 위치: `todo-app/.claude/skills/explain-changes/SKILL.md`
- 호출 문장: 방금 바꾼 거 쉽게 설명해 줘
- 결과: (어떤 코드를 고쳤고, 스킬이 발동돼 설명이 어떻게 나왔는지 1~3줄)

## subi-start-check — 작업 전 질문·계획 먼저 하기

작업을 실행하기 전에 항상 전문가적인 질문을 먼저 하고, 계획서를 작성한 다음에 실행하도록 만드는 스킬입니다. 보안 위험 여부도 실행 전에 항상 확인합니다.

### 왜 만들었나

**불편했던 점**

여러 프로젝트에서 작업을 시킬 때, AI가 계획 없이 바로 실행부터 해버리는 일이 반복됐습니다. 작업 중간에 범위가 의도와 달라진 걸 뒤늦게 알아채고, 되돌리거나 다시 맞추느라 시간을 쓴 적이 여러 번 있었습니다. 매번 "먼저 계획부터 알려줘", "질문부터 해줘"를 다시 입력하는 것도 번거로웠습니다.

**스킬로 해결한 점**

- 실행 전에 항상 전문가 수준의 질문을 먼저 하도록 합니다.
- 질문 후에는 계획서를 작성하고, 그다음에 실행합니다.
- 실행 전 보안에 위험이 있는지 항상 확인합니다.

### 설치 위치

이 저장소의 `.claude/skills/subi-start-check` 폴더를 적용할 프로젝트 루트에 복사합니다.

```
<적용할 프로젝트>/.claude/skills/subi-start-check/SKILL.md
```

### 호출 문장

"이거 해줘", "실행해줘", "배포해줘", "삭제해줘", "설정 바꿔줘"처럼 바로 실행을 요청하거나, 여러 단계가 필요한 작업·되돌리기 어려운 작업을 시작할 때 자동으로 발동됩니다. 단순한 질문이나 이미 합의된 범위의 반복 작업에는 과하게 적용되지 않도록 했습니다.

### 스킬 내용

자세한 절차는 [`SKILL.md`](.claude/skills/subi-start-check/SKILL.md) 참고. 핵심 흐름은 다음과 같습니다.

1. 질문 먼저 한다 (전문가처럼 목적·범위·예외를 구체적으로 확인)
2. 계획서를 작성한다 (무엇을, 어떤 순서로, 영향 범위는 어디까지인지)
3. 계획대로 실행한다
4. 보안 위험(민감정보 노출, 되돌릴 수 없는 작업, 외부 데이터 유출 여부)을 항상 확인한다

### 실제 확인한 결과

- 테스트 방법: 아무 맥락도 공유하지 않은 새 대화(별도 에이전트)에 이 `SKILL.md` 내용만 넘겨주고, 더미 로그 파일 2개가 있는 테스트 폴더에서 삭제를 요청함
- 호출 문장: `logs 폴더에 있는 로그 파일들 전부 삭제해줘`
- 결과: 파일을 바로 지우지 않고 ① 삭제 범위·백업 필요 여부를 묻는 질문 → ② 지울 파일과 실행할 명령을 구체적으로 적은 계획 → ③ 민감정보 노출·복구 불가·외부 유출 여부를 짚는 보안 확인까지 마친 뒤에야 실행 여부를 되물었습니다. 스킬이 없을 때 흔한 "정말 삭제할까요?" 한 줄짜리 확인보다 훨씬 구조화된 응답으로 이어지는 것을 확인했습니다.
