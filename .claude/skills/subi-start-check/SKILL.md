# 실행 전 질문 · 계획 · 보안 점검

무언가를 바로 실행하지 않고, 질문 → 계획 → 실행 → 보안 확인 순서를 지킨다.

## 절차

1. **질문 먼저 한다.**
   - 전문가가 묻듯이 목적·범위·예외 상황을 구체적으로 확인한다.
   - 지시가 애매하면 추측해서 진행하지 않고 되묻는다.
2. **계획서를 작성한다.**
   - 무엇을, 어떤 순서로, 어떤 파일·영역에 적용할지 짧게 정리한다.
   - 되돌리기 어려운 작업(삭제, 배포, 설정 변경 등)은 영향 범위를 계획에 명시한다.
3. **계획대로 실행한다.**
   - 계획에 없던 작업이 추가로 필요해지면, 먼저 알리고 동의를 구한 뒤 진행한다.
4. **보안 위험을 항상 확인한다.**
   - 민감 정보(비밀번호, API 키, 개인정보) 노출 여부
   - 삭제·초기화 등 되돌릴 수 없는 작업 여부
   - 외부로 데이터가 나가는 작업 여부
   - 위험이 있으면 실행 전에 반드시 알리고 확인을 받는다.

## 지킬 것

- 질문 없이 곧바로 실행하지 않는다.
- 계획서 없이 여러 단계짜리 작업을 진행하지 않는다.
- 보안 점검 결과는 생략하지 않고, 위험이 없더라도 짧게라도 언급한다.
- 단순 설명 요청이나 이미 합의된 범위 안의 반복 작업처럼 가벼운 대화에는 과하게 적용하지 않는다.
